Assignment 5: Government Data API

Author

Cecilia Chen

1. Introduction

This assignment uses the GovInfo website and API to retrieve Congressional Hearings associated with the U.S. Senate Committee on Foreign Relations.

The objective is to compare manual website exports with API-based collection, download ten hearing documents, and evaluate their usability as research data.

2. Data Collection: Website Search

The GovInfo website was searched using the following parameters:

3. GovInfo API Search

The API search was performed using a POST request with the same collection and keyword query.

Show R Code 
library(httr2)

body <- list(
  query = 'collection:(CHRG) AND "Committee on Foreign Relations"',
  pageSize = 100,
  offsetMark = "*",
  sorts = list(
    list(
      field = "publishdate",
      sortOrder = "DESC"
    )
  )
)

found <- request("https://api.govinfo.gov/search") |>
  req_url_query(
    api_key = Sys.getenv("GOVINFO_API_KEY")
  ) |>
  req_body_json(body) |>
  req_perform() |>
  resp_body_json()

The API returned 1,202 matching records, with 100 records in the first response.

The response contained count, offsetMark, and results. The results field contained nested document records that were converted into a dataframe.

6. Report and Reflection

6.1 How Usable Are the Documents as Data?

The downloaded PDFs are useful as source documents, but they are not immediately ready for structured text analysis.

To convert them into a corpus, I would need to extract the text from each document, remove repeated headers and footers, and preserve the relationship between each text and its metadata.

If some documents contain scanned pages rather than embedded text, optical character recognition (OCR) may be necessary.

I would also need to examine the quality of extracted text because formatting issues, missing passages, and extraction errors could affect subsequent analysis.

A possible corpus structure would contain one row per hearing, with columns for the document ID, title, publication date, and extracted text.

6.2 How Could the Collection Process Be Improved?

The API response includes links to other document formats, including text-related resources.

Using machine-readable text or HTML, where available, could reduce the difficulties associated with extracting data from PDFs.

Metadata such as packageId, title, and dateIssued also make it possible to organize documents without manually opening every file.

For a larger project, I would automate the collection and validation process, retain download logs, and cache both metadata and source documents.

I would also verify committee attribution using document metadata or the hearing text rather than relying only on keyword matches.

6.3 What Did the API Provide That Website Search and Scraping Did Not?

The API provided structured metadata and a programmable way to retrieve document information and download links.

Unlike manual website searches, API requests can be recorded, repeated, and incorporated into an automated data collection workflow.

The API also supports pagination, which makes collecting larger sets of documents more manageable.

However, API access does not eliminate the need to check search coverage, document relevance, and data quality.

7. Data Provenance and Limitations

Source: U.S. Government Publishing Office, GovInfo.

Collection: Congressional Hearings (CHRG).

Search query: collection:(CHRG) AND "Committee on Foreign Relations".

Search date: October 13, 2026.

Sort order: Publication date, descending.

Website search results: 1,202 matching records.

API search results: 1,202 matching records, with 100 records returned in the first response.

Selected records: Ten most recent search results.

Data files: Website export, API metadata, comparison results, and download log.

Local document storage: govinfo_pdfs/, excluded from the public repository.

The main limitation is that the search matches documents containing the committee name. This does not automatically establish that every matching document was produced by the Senate Committee on Foreign Relations.

The ten selected records therefore remain subject to committee-level verification before they could be treated as a fully validated research sample.

The website and API also returned two same-date documents in a different order, demonstrating why record identifiers are important for comparing data sources.

8. Conclusion

This assignment demonstrates how a government API can support reproducible document collection.

The website and API returned the same ten document IDs, and ten PDF files were successfully downloaded and passed basic file-format validation.

The exercise also highlights the importance of checking search results, documenting collection methods, and distinguishing successful downloads from analysis-ready data.
