urls <- paste0(
  "https://books.toscrape.com/catalogue/page-",
  1:5,
  ".html"
)

scrape_page <- function(page_url) {

  page <- read_html(page_url)

  books <- page |>
    html_elements("article.product_pod")

  titles <- books |>
    html_element("h3 a") |>
    html_attr("title")

  prices <- books |>
    html_element("p.price_color") |>
    html_text2()

  rating_classes <- books |>
    html_element("p.star-rating") |>
    html_attr("class")

  ratings <- sub("star-rating ", "", rating_classes)

  data.frame(
    title = titles,
    price = prices,
    rating = ratings
  )
}

pages <- lapply(urls, scrape_page)

books_5pages <- do.call(rbind, pages)

The original Wikipedia table contained a multi-row header and several columns that were not needed for the comparison. I removed the two header rows, kept the country, continent, reserves including gold, and reporting date, and converted the reserve values to numeric form.

One observation for Albania reported the date as 31 Apr 2024, which is not a valid calendar date. I retained the observation but allowed the date to become missing rather than guessing the intended date.

Changing the target table broke several assumptions from the first scraper. The foreign-exchange table was the third table on its page, contained eight columns, and included two header rows inside the extracted dataframe. In contrast, the population table was the first table, contained six columns, and its first row was a real World observation rather than an embedded header.

The date structure also changed. Most population observations reported a complete day-month-year date, but 10 observations reported only a year. I preserved this difference in precision rather than assigning an artificial month or day to year-only observations.

3. World Bank WDI Comparison

Fetching the same quantity from the World Bank

wdi_reserves <- WDI::WDI(
  country = "all",
  indicator = "FI.RES.TOTL.CD",
  start = 2024,
  end = 2026
)

wdi_latest <- wdi_reserves |>
  filter(!is.na(FI.RES.TOTL.CD)) |>
  group_by(country) |>
  slice_max(year, n = 1, with_ties = FALSE) |>
  ungroup() |>
  mutate(
    reserves_million_usd = FI.RES.TOTL.CD / 1e6
  )

The WDI indicator is reported in current US dollars, while the Wikipedia table reports reserves in US$ millions. I therefore divided the WDI values by one million so that the two sources use the same unit.

real_countries <- WDI::WDI_data$country |>
  filter(region != "Aggregates") |>
  select(iso3c)

wdi_countries <- wdi_latest |>
  semi_join(real_countries, by = "iso3c")

World Bank regional and other aggregate observations were removed so that the comparison only used country-level entities.

Wikipedia reports a country-specific last-reported date, while the WDI observations returned by this query were annual values from 2024 or 2025. Therefore, many differences between the two sources can be explained by different reporting vintages.

However, substantial differences remained even when both observations came from the same calendar year. For example, South Sudan, São Tomé and Príncipe, Gabon, North Macedonia, and the United States showed large differences. This suggests that reporting vintage alone does not explain all discrepancies; source definitions, reporting practices, and data quality may also contribute.

When is scraping the right tool?

Scraping is appropriate when useful data are available on a web page but no usable API or structured download exists. When a documented API or bulk dataset is available, I would generally prefer it because it provides a more stable and reproducible interface than relying on webpage structure.

4. Data Plan

My research interest is how generative AI affects students’ information-seeking and evaluation behavior. For a web-based data collection project, I would collect public YouTube videos and comments related to students’ use of generative AI for studying, information searching, and academic work. YouTube is a useful source because students and educators publicly discuss how they use tools such as ChatGPT, what kinds of information they rely on, and how they evaluate AI-generated information. I would focus on videos and comments explicitly related to studying, research, fact-checking, or academic use of generative AI rather than general AI content.

I would use the official YouTube Data API rather than scraping YouTube webpages. Before collecting data, I would review YouTube’s Terms of Service and API policies to make sure that the planned collection and storage are permitted. Because YouTube provides structured access to public information through an API, scraping the HTML pages would not be necessary for this project. The API is also preferable because its fields are documented and less dependent on the visual structure of webpages.

I would begin with a defined set of search terms, such as “ChatGPT studying,” “AI for research,” and “students using ChatGPT.” I would first retrieve a limited set of relevant video IDs and then collect metadata and available public comments for those videos. Because the YouTube Data API uses a quota system, I would avoid repeatedly making unnecessary search requests. I would save retrieved video IDs and raw data locally and reuse these cached files during later stages of the project.

At the pilot stage, I would keep the collection relatively small, with dozens of videos and potentially several thousand comments. I would collect the data in batches and record the date of collection, search terms, video IDs, and API parameters so that the process can be reproduced. Raw API data would be stored separately from cleaned analysis data.

Possible failures include changes to API fields, deleted or unavailable videos, disabled or deleted comments, and changes in search results over time. I would detect these problems by checking the number of returned records, expected variable names, missing values, and API error messages each time the script runs. I would also keep a small set of known video IDs as a validation sample so that unexpected changes in API output can be detected.
